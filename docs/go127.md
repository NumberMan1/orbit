# Go 1.27 与 JSON v2 适配

`go.mod` 声明 `go 1.27.2`，`.go-version` 和 CI 都固定为 1.27.2；Makefile 的检查要求 `go env GOVERSION` 精确匹配，并设置 `GOTOOLCHAIN=local`。注意：Go 的 go directive 是最低版本约束，本身不会阻止使用更高版本编译，所以通过构建入口和 CI 约束实际验证版本。

## JSON v2

Go 1.27.2 默认可直接导入 `encoding/json/v2`，无需手动设置 `GOEXPERIMENT`。项目构建和 CI 使用工具链默认配置：

```sh
go test -race ./...
go run ./examples/echo -config examples/echo/config.yaml
```

第三方库继续使用 `encoding/json` 的 v1 兼容语义。Orbit 自身的 codec、etcd Descriptor 和 HTTP 辅助函数直接使用 v2 API，没有保留 v1 回退层，也没有引入第三方 JSON 包。升级 JSON v2 属于协议行为变化，应用需要检查自己的类型与序列化约定：

- 默认拒绝重复对象字段（包括转义后相同的名字）及非法 UTF-8。etcd 中这些记录会触发 Store 保留旧快照、取消就绪并等待修复。
- 字段名默认大小写敏感，建议为协议字段显式声明 `json` tag。HTTP DecodeJSON 通过 `RejectUnknownMembers(true)` 拒绝未知字段；通用 codec、HTTP 响应解码和 Descriptor 仍允许未知扩展字段，大小写不匹配的字段不会自动匹配。
- nil slice/map 默认输出 `[]`/`{}`，而不是 `null`。`omitempty` 根据 JSON 空值省略，数字 0 和布尔 false 不再因该 tag 被省略；按 Go 零值省略应使用 `omitzero`。
- map 输出顺序默认不保证稳定；不要把原始 JSON 字节顺序当作业务等价性或签名依据。
- time.Duration 默认没有隐式纳秒表示，需要按业务协议明确格式；自定义 MarshalJSON/UnmarshalJSON 也应验证其 v2 行为。

HTTP DecodeJSON 使用 `UnmarshalRead` 配合 MaxBytesReader，读取至 EOF 并拒绝尾随 JSON、未知字段、重复名字和超限正文；HTTP 写出示例使用 `MarshalWrite`。回归测试覆盖上述边界、空集合/省略规则和 Descriptor 校验。

## 沿用的现代标准库能力

- **Go 1.25 `sync.WaitGroup.Go`**：用于监听器内会话任务和应用监督任务，把 Add、启动 goroutine、Done 绑定在一起。按标准库约定，传入函数不能向外传播 panic；Session 自身在用户回调边界处理 panic。
- **Go 1.25 `testing/synctest`**：队列、定时和 Store 恢复测试使用虚拟时间，验证取消、背压和排空，避免通过长时间 sleep 猜测执行顺序。真实网络仍使用真实回环连接和截止时间测试。
- **Go 1.25 容器感知 GOMAXPROCS**：不再通过 `runtime.NumCPU` 或环境无关的常数覆盖默认值，允许 runtime 依据容器 CPU 配额调整。应用需要覆盖时自行显式配置。
- **现代 context**：使用 CancelCause 保留退出原因、AfterFunc 唤醒阻塞 I/O、WithoutCancel 创建有界清理上下文；拨号、数据库操作和 etcd 请求均支持取消。
- **类型化原子与泛型**：Session ID 使用 `atomic.Uint64`，单次运行使用 `atomic.Bool`；配置泛型加载保持具体类型，避免旧反射属性接口；`discovery.Store` 使用 `atomic.Pointer` 发布不可变快照，`maps.Clone` 用于隔离快照所有权，`math/rand/v2` 为重试添加抖动。
- **结构化日志**：直接使用 `github.com/NumberMan1/log v0.3.1` 的 Logger/field；日志 core 由应用拥有，框架仅借用，不内置业务字段或 Elasticsearch 上传。日志依赖自身仍使用其发布版本的 JSON 实现，不改变 Orbit 协议的 JSON v2 约定。
- **现代计时语义**：使用可停止的 Timer/Ticker 和单调时间，不手动实现旧版 stop/drain/reset 模式，不保留每 5ms 轮询全局启动状态的循环。虽然新版 runtime 可回收未引用计时器，仍主动 Stop，以表达资源生命周期。
- **现代 HTTP 路由**：示例使用标准库 `GET /healthz` 路由模式，无额外 Web 框架；每个服务器有独立 handler，不暴露 DefaultServeMux 上隐式注册的调试路由。

JSON 直接使用标准库 `encoding/json/v2`，不设置实验开关。其他能力继续使用现代标准库 API。为保留旧框架按 key 管理大量定时任务的能力，提供可选的 `timewheel.TimeWheel[K]`，与标准定时器共存，详见 [定时器选择](timers.md)。是否采用时间轮、零拷贝或内存池等优化，仍需按实际工作负载评估。

## 依赖与可移植性

Protobuf 更新到官方现代 API；etcd 使用模块化 v3 客户端，去掉旧 coreos/etcd 与 grpc replace 链。YAML v3 支持严格字段校验。Redis 保持 context 化 v8 API，MySQL/GORM 使用当前声明的固定版本。`go.sum` 随仓库提交以便校验依赖。

TCP/HTTP/WebSocket 不依赖平台专用 `SO_REUSEPORT` 或不完整的 linux/windows 文件对；通过标准库跨平台构建。TLS 参数由应用提供，密钥和证书不嵌入框架。

版本固定满足本次迁移约束，不代表未来可以省略补丁升级与依赖安全维护。后续升级应先运行全部测试、集成测试和目标平台构建，单独审查协议及行为变化。
