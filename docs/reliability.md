# 故障处理、观测与运行扩展

这些能力由 Orbit 进程内组件提供，不要求新增开源项目或独立服务。

| 能力 | 放置位置 | 外部系统或应用负责 |
| --- | --- | --- |
| Ping/Pong、超时失活、RTT | request.Heartbeat | 心跳 ID、间隔、重连与业务就绪策略 |
| 熔断、单次恢复探测、排空过滤 | discovery.Balancer、Pool、Picker | 业务错误分类、节点状态发布、实体所有权 |
| 请求级错误与远端取消 | request.Server/Client、gateway | 错误码、幂等、事务回滚、协议启用协商 |
| 耗时、排队、关联标识 | observe、socket/request 的 Observer | 指标存储、告警、看板、完整分布式追踪后端 |
| 按实体串行执行 | service.Shards | 实体模型、跨节点迁移、分片规模选择 |
| 安全配置热更新 | config.Live | 可热更字段、重载入口、配置分发与权限 |

只有适配器需要跨多个项目复用、独立版本发布时，才值得拆成另一个 SDK。配置中心、指标存储等有独立部署生命周期，可以由外部系统承担；Orbit 不内置第二套这类服务。

## 兼容与接入顺序

默认帧头、Client 原始载荷、Forward 的错误关闭策略保持不变。新协议能力必须显式启用，不能直接发给旧端点。

1. 为请求、响应、取消、Ping/Pong 分配互不冲突的应用消息 ID。
2. 每个连接只创建一个 request.Client；所有响应和心跳共用唯一序号空间。启用 Metadata 时，心跳请求列入 RawRequestIDs。
3. 后端使用 RespondHeartbeat 包装 request.Server.Handler；后者在有界异步任务中执行请求，读循环继续接收控制消息。处理函数要支持并发并遵守 context。
4. 每次转发通过 Balancer.Acquire 获取 Selection；路由建立失败或调用结束都调用 Complete。任何返回路径都不能遗忘半开探测名额。
5. 对外网关用 ForwardWithOptions.OnError 编码有限的公开错误，禁止直接透传内部错误原文。客户端仍需检查业务响应内容。
6. 请求处理入口捕获配置快照；需要按实体串行时投递 Shards。已有组件不会因为配置版本更新而自行重建。

完整接线见 [网关示例](../examples/gateway/README.md)，P2 用法见 [runtime 示例](../examples/runtime/README.md)。

## 排空与故障恢复

节点先通过 Registration.Update 发布 Metadata[discovery.DrainingMetadata]="true"。Pool 看到单独的排空元数据变化时保留连接，Picker/Balancer 停止新选择；随后本机 Quiesce/Drain 完成已经接受的工作。目录传播是最终可见的，本机仍必须拒绝新工作；需要的传播等待由部署层安排。

熔断按 Session 隔离，连接重建后从新状态开始；连续失败达到阈值才冷却。冷却后第一个请求承担恢复探测，其余请求避开该节点。探测成功恢复服务，失败或取消重新冷却；不会自动重放失败的操作。调用方必须给实际请求设置超时并保证 Complete 执行。

远端取消是尽力发送的控制帧，元数据截止时间提供另一条取消路径。即使取消已送达，处理函数不返回仍占用并发名额，防止“超时但工作继续”的任务无限堆积。时钟同步、合作式取消和幂等策略仍是应用部署契约。

## 验证与容量边界

测试覆盖迟到 Pong、连续失活、跨会话取消隔离、取消后名额占用、元数据截止时间/关联标识、单探测恢复、迟到熔断结果、排空不换连接、错误回包后继续调用、分片 FIFO/背压/并行和配置失败回滚。
这些测试不等同于生产容量结论；持续负载、多节点故障切换和滚动部署仍应按目标拓扑与负载验证。
